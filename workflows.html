전체업무순서 워크플로우

name: 전체업무순서 inputs: 사용자 요청, agentis/agent.md 의 primary tasks, 업무별 입력 자료 outputs: 업무 산출물, 검증 결과, memory/log.md·hot.md 갱신, 루트 workflows.html·holonomic brain.html…

문서전용
  1. `agentis/agent.md` 를 읽어 에이전트 이름, 목적, `primary_tasks` 를 확인한다.
  2. `agentis/memory/hot.md`, `agentis/memory/log.md` 마지막 20줄을 읽어 진행 중/대기 중 업무를 확인한다.
  3. 사용자 요청이 `primary_tasks` 중 어느 항목인지 분류한다.
  4. 해당하지 않으면 부수 업무로 처리할지, 새 주요 업무/workflow로 추가할지 사용자에게 한 가지만 묻는다.
  5. `.clinerules/workflows/` 에 해당 업무명 또는 가장 가까운 workflow가 있으면 그 파일을 따른다.
  6. 없으면 `agentis/workflows/` 에 있는 `.workflow.md` 를 확인한다.

메모리 lint

name: memory lint inputs: agentis/agent.md + agentis/memory/ / .md outputs: 콘솔 보고서 / report 보고서 파일 / fix 깨진 링크 주석화 script: memory lint.py created: 2026 05 26 up…

문서전용명령 4
  1. 콘솔에 보고서 출력. 안전 — 파일 안 건드림.
  2. **깨진 링크만** 자동 처리: `[[X]]` → `<!-- TODO: 깨진 링크 [[X]] -->` (원본 텍스트 보존, 그래프에서만 빠짐).
  3. 고아 페이지·중복 페이지는 **자동 삭제 X** — 사용자 결정 필요. 보고서로만.
  4. 깨진 링크 — 페이지 이름 변경이면 링크 텍스트만 고침. 페이지 삭제됐다면 주석 그대로 유지(역사 기록).
  5. 고아 페이지 — 정말 안 쓰는 페이지면 `_index.md` 에서 내리고 페이지에 `tags: [archived]` 추가. 삭제는 신중히.
  6. 중복 페이지 — 두 페이지 중 더 잘 정리된 쪽을 *기준*으로, 다른 쪽 내용을 머지해서 기준 페이지로 흡수. 흡수된 쪽은 `_index` 에서 내리고 frontmatter 에 `merged_into: [[기준페이지]]` 메모.

문서전용명령 3

  5. 정말 안 쓰는 스킬인가? (계절성·연 1회만 쓰는 것도 있음)
  6. 안 쓰는 이유가 *스킬이 별로*여서인가, *지금 일이 없어서*인가?

메인 동기화

name: 메인 동기화 inputs: agent.md 의 main repo: 필드 사내 깃 메인 에이전트 레포 URL . 없으면 비활성 outputs: pull → 팩 병합 실행 / push prep → 푸시 준비 폴더 + git 명령 안내 / check → 디프 요약 script: 메…

문서전용명령 3
  1. 메인 레포의 구조는 **루트에 `agent.md` + `memory/` + `skills/` + `workflows/`** 가 있는 형태를 가정한다. 다르면 `--repo-subpath <경로>` 로 안의 위치 지정.
  2. `git` 이 설치돼 있어야 함. 없으면 에러로 종료.
  3. 사내망 인증서 문제로 클론 실패 시 가이드 메시지 출력. 사내 깃 사용자명/토큰은 사용자 환경 (`git config --global` 또는 `~/.git-credentials`) 그대로 사용 — 스크립트가 직접 다루지 않음.
  4. 메인 큐레이션(여러 사람 브랜치 → 메인 갱신)은 관리자가 [브랜치-비교](브랜치-비교.workflow.md) 보고 결정해서 메인 레포에 직접 커밋.

브랜치 내보내기

name: 브랜치 내보내기 inputs: 이 에이전트의 agentis/ 폴더 + 선택 사용자가 지정한 추가 제외 경로 outputs: <에이전트이름 브랜치 YYYY MM DD/ 폴더 BRANCH.md + seed/ + fork/ + pack/ script: 브랜치 내보내기.py crea…

문서전용명령 1
  1. 자동 제외 정책 설명: 사용자 본인 식별 정보(`agent.md` 안), 본인 엔티티 페이지, `share: private` 태그 페이지.
  2. 추가 제외 의사 확인: "더 빼고 싶은 게 있을까요? 없으면 '없음' 이라고 답해주세요."
  3. 통계: 포함 N파일 / 제외 M파일 (자동 / 사용자 지정)
  4. 의심 누출 경고: 사람 이름 / `[REDACTED]` 잔류 / 소스 링크 등이 fork 본문에 남아있는지 보고
  5. 출력 폴더 경로 + `BRANCH.md` 보기 안내
  6. 인터뷰에서 추가 제외 받을 때 명시적으로 묻는다. "별도 제외 없으면 케이스 데이터까지 다 같이 가요" 가 보낸 사람 의도와 맞는지 확인.

브랜치 비교

name: 브랜치 비교 inputs: 두 개의 경로 브랜치 폴더 또는 agentis 폴더 . 각각 skills/ , workflows/ , memory/concepts/ 가 있어야 함 outputs: 디프 보고서 마크다운 한 장 script: 브랜치 비교.py created: 2026…

문서전용명령 1
  1. 한쪽에만 있는 것 (=양쪽에 다 채택 후보)
  2. 양쪽에 같은 이름 / 내용 동일 (=이미 정렬됨)
  3. 양쪽에 같은 이름 / 내용 다름 (=충돌, 사람 결정 필요)
  4. 이름은 다른데 비슷한 의미일 가능성 (=의심 후보, 사람 확인)
  5. 내용 비교는 **정규화된 텍스트 해시**(공백/줄바꿈 정규화)로 한다. 의미적 동일성은 사람이 판단.
  6. "비슷한 이름" 휴리스틱은 단순(서로의 슬러그가 다른 쪽 슬러그의 prefix/suffix 인지) — 진짜 의미 매칭은 사람 몫.

씨드 업그레이드 (씨드 자체의 공유와 진화)

name: 씨드 업그레이드 inputs: 자기 씨드 .clinerules / agentis.md + 표준 씨드 from 또는 .kit mirror/seed/agentis.md outputs: seed upgrade report.md + plan.json check / 갱신된 자기 씨드…

문서전용명령 3
  1. 표준 씨드 경로 안 주면 `agentis/.kit-mirror/seed/agentis.md` 자동 탐색.
  2. 출력: `seed-upgrade-report.md` + `plan.json` 템플릿 (각 절의 action 기본값이 채워져 있음).
  3. `NEW` 절: "§7 <제목> 새로 생겼어요. 받을까요?" (보통 `take`)
  4. `DIFF` 절: "§1-2 — 표준도 보강됐고 사용자도 추가하셨네요. ① 머지 ② 내 것 유지 ③ 표준으로 덮기 중 어떻게 할까요?"
  5. 머지가 결정되면, 사용자(또는 너 = LLM)가 두 절을 머지한 텍스트를 `merged-1-2.md` 같은 파일로 저장하고, plan.json 의 해당 항목 action 을 `replace-with-file:merged-1-2.md` 로 바꾼다.
  6. `LOCAL-CUSTOM` 절: 보통 `keep` (그대로 유지).
.clinerules/workflows/씨드-업그레이드.md

팩 병합 (다른 에이전트의 역량만 가져오기)

name: 팩 병합 inputs: 브랜치 폴더 안의 pack/ 경로 + 이 에이전트의 agentis/ outputs: 합쳐진 agentis/skills/ , agentis/workflows/ , agentis/memory/concepts/ + memory/log.md 한 줄 script…

문서전용명령 2
  1. 덮어쓰기 (overwrite): 팩의 새 버전으로 교체
  2. 내 것 유지 (keep-mine): 내 기존 것을 그대로
  3. 둘 다 (rename-incoming): 팩의 것을 `<원이름>-import` 로 이름 바꿔서 같이 두기
  4. 콘솔: 추가 / 덮어쓰기 / 스킵 통계 + 안전 보장(agent.md 등 안 건드림) 확인 메시지
  5. 머지 후 `python agentis/graph/build_graph.py` 한 번 돌려 그래프 갱신
  6. 팩의 `pack.meta.md` 를 먼저 읽어 출처·범위를 확인하고 사용자에게 알린다.
