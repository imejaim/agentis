# skills/ — 에이전트가 키워가는 스킬

스킬 = "전에도 했고 앞으로도 또 할 작업"을 재사용 가능하게 묶은 것. (Hermes처럼 에이전트가 일하다가 *스스로* 만들자고 제안하고, 사용자가 승인하면 추가됨. superpowers처럼 "그냥 참고용 글이 아니라 실제로 따르는 절차".)

## 구조

```
skills/
  _index.md           ← 스킬 목록 (이름 — 한 줄 설명 — 트리거 조건)
  <스킬이름>/
    SKILL.md          ← 언제 쓰는지 + 절차 + 주의사항 (+ 입력/출력)
    run.py            ← (가능하면) 결정론적 구현. 입력/출력 경로를 인자로 받게.
    (그 외 필요한 리소스)
```

## SKILL.md 포맷

```markdown
---
name: <스킬이름>
trigger: <언제 이 스킬을 쓰는가 — 한 줄. 에이전트가 작업 들어가기 전에 _index 보고 매칭>
inputs: <필요한 입력>
outputs: <만들어내는 산출물>
created: 2026-05-13
---

# <스킬 제목>

## 언제
<이 스킬이 적용되는 상황. 적용 안 되는 경우도 명시.>

## 절차
1. ...
2. 가능한 단계는 `run.py` 로 (결정론). 예: `python skills/<이름>/run.py --in <경로> --out <경로>`
3. ... 검증 단계 (출력이 기대대로인지 확인) ...

## 주의
<자주 틀리는 지점, 엣지 케이스, 사람이 꼭 확인해야 하는 부분>

## 관련
- 메모리: [[concepts/...]], [[entities/...]]
- 워크플로우: ../workflows/...
```

## 만드는 시점

에이전트가 어떤 일을 하고 나서 "이거 또 할 것 같은데?" 싶으면 사용자에게: **"이거 스킬로 만들어 둘까요?"** → 승인 시 위 구조로 만들고 `_index.md` 에 등록하고 `memory/log.md` 에 `## [날짜] skill | <이름> 추가` 기록. 다음에 비슷한 일이 오면 그 스킬을 먼저 쓰고, 부족하면 그 자리에서 개선한다(= 진화).
