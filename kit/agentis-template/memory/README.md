# memory/ — 에이전트의 "두뇌" (살아있는 LLM-위키)

세션이 바뀌어도 에이전트가 기억하는 건 **이 폴더가 전부**입니다. 매 세션 시작 시 읽고, 작업이 끝날 때마다 갱신합니다. (RAG가 아니라 — Karpathy의 LLM-위키 패턴: 지식을 한 번 "컴파일"해서 계속 최신으로 유지.)

## 구조

```
memory/
  _index.md      ← 모든 페이지 목록 (카테고리별, [[페이지]] — 한 줄 요약). 새 페이지 만들면 여기 등록.
  overview.md    ← 이 업무/도메인의 큰 그림. 새로운 큰 사실이 생기면 갱신.
  log.md         ← 연대기 (append-only). 한 줄씩: ## [YYYY-MM-DD] <type> | <제목>
  hot.md         ← 지금 작업 중인 것 / 열린 쟁점 / 다음 할 일. 짧게 유지(오래된 건 정리).
  concepts/      ← 개념 페이지. 원자 단위 — 하나당 한 개념. 예: rohs-제한물질.md
  entities/      ← 엔티티 페이지. 사람/시스템/문서/프로세스/규격 등. 예: kc-인증.md, 홍길동.md
  sources/       ← 받은 자료의 요약 페이지. 원본은 절대 수정하지 않음. 예: 2026-05-13-시험성적서-A.md
```

## 페이지 포맷 (concepts / entities / sources 공통)

```markdown
---
type: concept            # concept | entity | source
tags: [태그1, 태그2]
created: 2026-05-13
updated: 2026-05-13
source_count: 0          # (선택) 이 페이지가 몇 개 소스에서 합성됐는지
---

# 페이지 제목

본문. 원자 단위로 — 한 페이지 = 한 주제. 다른 페이지를 [[entities/kc-인증]] 처럼 링크.
새 사실이 기존 내용과 어긋나면 그 자리에 "⚠ 2026-05-13 자료 B와 상충: ..." 라고 명시.
```

- **링크는 항상 `[[경로/페이지]]` 또는 `[[페이지]]`** (Obsidian식). 그래프 빌더(`graph/build_graph.py`)가 이 링크를 읽어 그래프를 만든다. 링크가 곧 시냅스다 — 관련 있으면 링크해라.
- 파일명은 한글 가능, 공백 대신 `-`. 예: `concepts/제한물질-농도-한계.md`.
- 페이지가 너무 커지면(한 화면을 한참 넘으면) 쪼개라. 작고 잘 연결된 페이지가 좋다.

## 언제 갱신하나 (작업이 끝날 때마다)

1. 새 개념/엔티티 등장 → `concepts/` 또는 `entities/` 에 페이지 생성 + `[[..]]` 로 연결 + `_index.md` 등록.
2. 자료를 받았다 → `sources/` 에 요약 페이지 + 거기서 알게 된 걸 관련 concept/entity에 반영.
3. `overview.md` 가 낡았으면 갱신.
4. `log.md` 에 한 줄: `## [YYYY-MM-DD] task | <한 일>` (type: `setup`|`task`|`ingest`|`skill`|`lint`|`note`).
5. `hot.md` 갱신: 방금 한 일 / 남은 일 / 열린 쟁점. 오래된 항목 제거.
6. 메모리가 바뀌었으면 그래프 갱신: `python agentis/graph/build_graph.py`.

> 한 작업이 10~15개 페이지를 건드리는 게 정상이다. 이게 두뇌가 자라는 방식이다 — 귀찮아하지 마라.

## 점검 (lint) — 가끔

사용자가 "메모리 정리해줘" 하면: 페이지 간 모순, 낡아서 갱신 안 된 주장, 인바운드 링크 없는 고아 페이지, 페이지가 있어야 하는데 없는 개념, 빠진 상호링크를 찾아 고치고 `log.md` 에 `## [날짜] lint | ...` 기록.
