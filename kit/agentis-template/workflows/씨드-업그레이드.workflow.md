# 씨드 업그레이드 (씨드 자체의 공유와 진화)

씨드(`.clinerules/agentis.md`) **자체**를 절(§) 단위로 비교·갱신·내보내기. 잘 다듬어진 사용자 씨드를 보존하면서 표준 씨드의 개선분을 흡수한다. **씨드 → 브랜치 → 메인 메타포의 씨드 층** (§5-5).

> 용어: 표준 씨드 = 메인 레포(`imejaim/agentis/seed/agentis.md`) 또는 사내 미러. 자기 씨드 = 사용자 작업 폴더의 `.clinerules/agentis.md`.

## 절 식별 — 어떻게 동작하나

씨드 v1.3+ 에는 각 절 시작에 `<!-- @section: N -->` 앵커가 박혀 있다. 스크립트가 이걸 키로 두 씨드를 자르고, 절별로 4가지 상태로 분류한다:

| 상태 | 의미 | 기본 권장 |
|---|---|---|
| `UNCHANGED` | 같음 | `keep` (변화 없음) |
| `NEW` | 표준에만 있음 (새 절) | `take` (받기) |
| `LOCAL-CUSTOM` | 내 씨드에만 있음 | `keep` (내 것 유지) |
| `DIFF` | 둘 다 있는데 다름 | `review` → 사람이 결정 |

## 절차

### A. 업그레이드 받기 (개인 사용자)

1. **확인** (변경 없이 보고만):
   ```
   python agentis/workflows/씨드-업그레이드.py --check --from <표준씨드경로>
   ```
   - 표준 씨드 경로 안 주면 `agentis/.kit-mirror/seed/agentis.md` 자동 탐색.
   - 출력: `seed-upgrade-report.md` + `plan.json` 템플릿 (각 절의 action 기본값이 채워져 있음).

2. **사람 결정** — 보고서 표를 사용자에게 보여주고, 절별로 묻는다 (한 번에 한 질문):
   - `NEW` 절: "§7 <제목> 새로 생겼어요. 받을까요?" (보통 `take`)
   - `DIFF` 절: "§1-2 — 표준도 보강됐고 사용자도 추가하셨네요. ① 머지 ② 내 것 유지 ③ 표준으로 덮기 중 어떻게 할까요?"
     - 머지가 결정되면, 사용자(또는 너 = LLM)가 두 절을 머지한 텍스트를 `merged-1-2.md` 같은 파일로 저장하고, plan.json 의 해당 항목 action 을 `replace-with-file:merged-1-2.md` 로 바꾼다.
   - `LOCAL-CUSTOM` 절: 보통 `keep` (그대로 유지).
   - `UNCHANGED` 절: 그대로 둠.

3. **적용**:
   ```
   python agentis/workflows/씨드-업그레이드.py --apply --plan plan.json --from <표준씨드>
   ```
   - 이전 씨드는 `agentis/.kit-mirror/seed/backup-YYYY-MM-DD.md` 로 자동 백업.
   - 새 씨드의 헤더 `seed-version` 은 표준 값으로 갱신, 사용자 `local-mods` 는 보존.

4. **검증** (사람 게이트):
   - 변경된 씨드를 사용자에게 보여주고 한 번 훑게 한다. 특히 `take` 한 절이 자기 흐름과 어긋나지 않는지.
   - `memory/log.md` 에 한 줄: `## [날짜] seed | upgrade vX → vY (적용 N / 보류 M)`.

### B. 씨드 브랜치 보내기 (잘 다듬은 사용자 → 메인 큐레이터)

```
python agentis/workflows/씨드-업그레이드.py --export-branch
```

- 출력: 작업 폴더 옆에 `seed-브랜치-YYYY-MM-DD/agentis.seed.md` + `SEED-BRANCH.md`(local-mods 요약·검토 체크리스트).
- 사용자가 zip / 사내 깃에 push 해서 큐레이터에게 송신.
- 큐레이터는 받은 씨드 브랜치를 `--check --from <받은씨드>` 로 표준과 비교 → 좋은 보강을 다음 표준 씨드에 반영.

## 의사결정 가이드 (자주 묻는 케이스)

- **NEW 절은 보통 받아라.** 새로 생긴 절은 다음 표준 흐름의 일부 — 빼면 다른 절과 어긋날 수 있다.
- **DIFF 절은 디프 본문을 본 뒤 결정.** 표준 보강이 사용자 보강을 포섭하면 `take`. 사용자 보강이 더 구체적이면 `keep`. 둘 다 살리고 싶으면 머지 파일 만들고 `replace-with-file:`.
- **LOCAL-CUSTOM 절은 그대로 유지.** 단, 너무 사적이거나 도메인 한정이면 다음 씨드 브랜치 송신 시 제외 고려.
- **seed-version 만 바뀐 절은 보통 `take`.** 의미상 변화 없는 정비.

## 주의 / 엣지 케이스

- 자기 씨드가 v1.2 이하(앵커 없음)이면 이 스크립트가 동작하지 않는다 → 한 번은 v1.3 표준 씨드를 통째로 받고(`cp <표준> .clinerules/agentis.md`), 그 다음부터 절 단위로 관리.
- `plan.json` 의 알 수 없는 action 은 안전하게 `keep` 으로 처리된다 (자기 절 유지).
- `replace-with-file:` 경로가 없으면 폴백으로 내 절 유지 + `skipped` 통계 카운트.
- 절 순서는 항상 **표준 순서**로 재배열되고, `LOCAL-CUSTOM` 절은 끝에 붙는다. 표준과 흐름을 맞추는 게 의도.
