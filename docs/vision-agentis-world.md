> 기록일: 2026-05-13 (대표님 두 번째 야간 메모 그대로 옮긴 것 + 가벼운 정리).
> 이건 **지금 만들 게 아니라 방향을 박아두기 위한 비전 문서**입니다. 구체화는 사용자가 늘고 메인이 운영되기 시작한 다음.

---

## 0. 한 줄 비전

**Agentis** = 에이전트들의 "**세상**". 모든 에이전트가 같은 씨드에서 출발하지만, 진화의 과정에서 도메인 유전자가 분기되어 종이 갈라지고, 그 분기 자체가 자동으로 분류·관리되는 곳.

---

## 1. 출발 관찰

여러 사용자가 자기 부서·자기 업무로 에이전트를 키우면 자연스럽게 무리가 생긴다:
- 시뮬레이션 돌리는 에이전트
- 문서 작성·전달 에이전트
- 제품 검증·측정 정리 자동화 에이전트
- 인사 서류 처리 에이전트
- 디버깅 짝꿍 에이전트
- …

**도메인은 다르지만 비슷한 "유전자"를 공유한다.** 예: 규격인증 파트의 문서 자동화 에이전트와 인사부서의 문서 자동화 에이전트는 다루는 문서가 달라도 **"문서 처리"라는 유전자**를 가진다. 검증·체크리스트·산출표는 둘 다 핵심 도구.

지금(v1.x)은 **하나의 공통 씨드**(`seed/agentis.md`)에서 출발한다. 비전은 진화 과정에서 **유전자가 갈라지듯 도메인 특화 씨드들이 자연 발생**하는 그림.

---

## 2. 그림 — 에이전티스 세상의 진화

```
        🌱 씨드 (공통 — 모든 에이전트의 출발)
              │
   ┌──────────┼──────────┬──────────┐
   ↓          ↓          ↓          ↓
  브랜치      브랜치      브랜치      브랜치       (각 사용자가 키운 진화체)
   │          │          │          │
   ├─→ 메인-A (사용자 자기 깃에 박는 표준)
   │   ↘
   │    ⇊ (능력치/도메인 분포가 어느 임계 이상)
   │
   └─→ 분류기 (자동) ──→ 🌱🌱 도메인 씨드들이 자연 발생
                            ├── 🧬 문서-유전자 씨드 (검증·체크리스트·표산출)
                            ├── 🧬 시뮬레이션-유전자 씨드 (파라미터·반복실행·통계)
                            ├── 🧬 측정·정리-유전자 씨드 (계측·교정·표산출)
                            └── 🧬 …
```

- 분기는 **사람의 분류 결정이 아니라 누적된 메인 에이전트들의 통계에서 자연 발생적으로 (clustering)** 만들어지는 것을 목표로.
- 새 사용자는 자기 업무에 맞는 **도메인 유전자 씨드**를 받아 시작 → 0에서가 아니라 이미 그 도메인의 기본기를 가진 상태에서.

---

## 3. 어디에 사는가

**에이전티스 = "장소"**. 후보:
- 사내 깃허브 / 깃랩 / 자체 깃 서버
- 또는 그 위의 가벼운 메타 서비스(스토리지 + 작은 인덱싱 스크립트)

깃이 잘 어울리는 이유: 버전 관리, 분기·머지가 핵심 메타포와 일치, 사내 인프라 친화. 다만 깃 위에 **"자동 분류·자연발생적 씨드 생성"** 레이어가 필요.

> 깃이 적절하지 않을 수도 있다 — 더 동적인 운영(주기적 분석·재분류)이 필요하면 깃 + 작은 큐레이션 봇 조합으로 갈 수도 있음. v3 단계에서 구체화.

---

## 4. 핵심 원칙 (지금 박아둘 것)

1. **사람 개입 최소** — 기존 모델(사용자가 올리면 다른 사용자가 검색해서 받아 쓰는 마켓플레이스)이 아니라, **자동 분류 + 자연발생적 종 형성**. Hermes 의 자가진화 정신을 *환경 레벨*로 확장.
2. **진화는 어디까지나 메인 단위에서만** — 개인 에이전트는 자유롭게 자라되, "종"(특수 유전자 씨드)이 되려면 누적된 메인들의 통계가 임계를 넘어야 함.
3. **씨드는 누적된 능력의 추상화** — 메인 알리스·밥·… 들의 공통 스킬/워크플로우/개념을 추출 → 신규 사용자가 받을 *기본 형질*로.
4. **공통 씨드는 영원히 0층에 있다** — 도메인 씨드는 0층의 자식. 부모를 절대 버리지 않음 (호환성과 일관된 부팅 보장).

---

## 5. 능력치(Character Sheet)와의 연결

§1차 작업으로 도입한 **에이전트 능력치(Level/XP/Speed/INT/Variety/Stamina/Wisdom + 도메인 태그 빈도)** 가 이 비전의 **기초 데이터**가 된다.

- **메인 후보 1차 판단**: 사용자가 자기 메인에 올리고 싶을 때 능력치가 일정 수준 이상인지 확인.
- **자연발생적 분류**: 다수 메인의 "도메인 유전자(상위 태그·스킬·워크플로우 시그니처)" 를 군집화 → 임계 넘으면 새 도메인 씨드 후보.
- **사용자 동기부여**: 캐릭터가 자라는 게 눈에 보임 = 계속 쓰고 싶어짐 = 데이터가 모임 = 세상이 두꺼워짐.

---

## 6. 단계 (먼 길)

- **지금 (v1.x)** — 능력치 자동 산출(`agent-stats.py`), 브랜치/팩/메인 메커니즘. 사용자별 깃 메인 가능.
- **v2** — 사내 메인 첫 운영, 관리자 워크플로우, `브랜치-비교.py` 보고서 큐레이션.
- **v3** — **에이전티스 깃 레포** (모든 사용자의 메인을 모아두는 곳). 주기적 분석 봇이 능력치·도메인 유전자를 집계.
- **v4** — **자연발생적 도메인 씨드 생성** — 군집화 결과 임계 넘으면 새 씨드 폴더 자동 생성(검토 후 채택). 신규 사용자에게 "어떤 도메인부터 시작?" 안내.
- **v5+** — 자가 진화 루프 본격: 도메인 씨드 자체가 시간에 따라 다시 분기·통합되며 "종"이 변동.

## 7. 미해결 질문 (다음에 구체화)

- **자연발생적 분류의 임계**가 무엇인가? (메인 수 N개 이상 + 도메인 유전자 거리 < ε 인 군집)
- **유전자 정의**: 상위 태그·스킬 이름·페이지 제목·워크플로우 시그니처 중 어디까지를 "유전자"로 볼지.
- **검토자**: 자동 도메인 씨드 생성을 100% 자동? 또는 관리자 1명의 가벼운 승인 게이트?
- **호환성**: 부모 씨드가 진화하면 자식 도메인 씨드들에 어떻게 propagate? (Linux 커널과 배포판의 관계와 유사)
- **이름**: 자동 생성되는 도메인 씨드의 이름은 누가 짓나? (군집 대표 태그 기반 + 사람 명명?)
