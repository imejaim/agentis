# Agentis 사내 깃 배포 가이드

> 사내 깃(GitHub Enterprise, GitLab, Gitea 등)이 생겼을 때 Agentis 씨드+키트를 올리고,
> 동료가 받는 흐름을 한 페이지로 정리.

---

## 한눈에 보기

```
[이 레포 씨드+키트]  →  사내 깃에 올리기  →  동료가 clone + 안녕
```

> **정본 사내 미러** = `https://github.sec.samsung.net/dongho-yoon/agent_seed`
> (삼성 사내 GitHub Enterprise, 씨드+키트만 포함. PLAN·examples·개발 잡파일 제외.)

배포 = **파일 공유**입니다. API 서버·Docker·별도 서비스 필요 없습니다.

---

## 1. 첫 푸시 (대표님이 한 번만)

```bash
# 1) 사내 깃에서 새 레포 생성 (이름 예: agentis-seed, 가시성: Internal 권장)

# 2) 이 레포의 배포본 추출 (개발 레포 루트에서)
python tools/build-dist.py --repo-url "<사내깃-URL>"
# → _dist/agentis-seed/ 생성됨
# 포함: install.py, .clinerules/agentis.md, seed/10-agent-routing.md, kit/agentis-template/
# 제외: examples/, docs/, tests/, PLAN.md, 개발/로컬 잡파일

# 3) 배포 레포로 push
cd _dist/agentis-seed
git init && git remote add origin <사내깃-URL>
git add . && git commit -m "feat: 첫 배포"
git push -u origin main
```

배포 레포 안에는 씨드(`.clinerules/agentis.md`), 키트(`kit/agentis-template/`), 설치 스크립트(`install.py`), 안내 README 만 들어갑니다. PLAN.md·examples·개발 잡파일은 빠집니다.

---

## 2. 동료가 받는 법

Cline 대화창에 아래 블록을 그대로 붙여넣으면 끝입니다.

```
이 사내 레포를 지금 이 작업 폴더에 셋업해줘:
<사내깃-URL>

순서:
1) 작업 폴더 안 임시 폴더에 git clone (자격증명 물으면 사내 계정으로).
2) 클론 폴더에서  python install.py  를 이 작업 폴더(프로젝트 루트) 대상으로 실행.
3) 임시 클론 폴더 삭제.
4) 다 되면 나에게 "안녕" 이라고 말 걸어줘.
```

`install.py` 가 `.clinerules/agentis.md` 와 `agentis/` 를 프로젝트 루트에 정확히 배치하고,
Cline이 워크스페이스 룰을 자동 인식 → "안녕" 한 마디로 인터뷰 시작.

---

## 3. Level 5 도달 → 사내 깃 알림

에이전트가 `python agentis/graph/agent-stats.py` 를 돌려 Level 5 이상이 되면
자동으로 다음을 안내합니다:

```
축하합니다! 이 에이전트를 사내 깃에 올려두면 동료들이 브랜치로 받을 수 있습니다.
준비되면 "사내깃-올리기" 라고 말씀하세요.
```

사용자가 승인하면 에이전트가 `agentis/workflows/사내깃-올리기.py --init` 을 제안합니다.
**새 레포 생성은 사람이 직접** (GHE 권한 문제) — 스크립트는 push 이후 단계만 자동화합니다.

---

## 4. 동료가 브랜치(패키지)로 받는 법

```bash
# 보내는 사람: 에이전트에게 "브랜치 만들어줘"
# → 내부적으로:
python agentis/workflows/브랜치-내보내기.py
# → <에이전트이름>-브랜치-YYYY-MM-DD/ 폴더 생성

# 받는 사람: 그 폴더를 자기 작업 폴더 옆에 두고 Cline 대화창에 "안녕"
# → 리브랜드 미니 인터뷰 자동 시작 (이름·환경 다듬기)
```

사내 깃이 있으면 폴더 대신 **레포 URL** 공유도 됩니다. `agent.md` 의 `main_repo:` 필드에
사내 레포 URL 을 넣으면 Level 5 이상부터 자동 푸시 옵션이 활성화됩니다.

---

## 5. 주의사항

- **처음 clone 시 자격증명**: 동료 PC에서 최초 1회 사내 GHE 계정 입력이 필요할 수 있습니다. 막히면 사내 IT 안내에 따라 PAT(Personal Access Token) 발급 후 사용.
- **Internal 가시성 권장**: 동료를 일일이 초대하지 않아도 사내 GHE 계정이면 클론 가능.
- **외부 자동 미러 X**: 사내망에서 외부 github.com 으로 나가는 자동화는 아웃바운드 차단으로 불가. 외부→사내 동기화는 수동으로.

## 0. 결론 먼저

- 방향 **OK**. zip 복붙보다 깔끔하고, "에이전트가 모이는 곳" 비전과도 맞음.
- 단, **"URL 한 줄"만으로는 안 된다.** 처음 켠 Cline은 맨몸이라 *어느 게 씨드인지*
  모름(부트스트랩 역설). → 우리가 배포하는 진짜 "제품"은 **URL + 복붙 1블록(설치 프롬프트)**
  이고, 그 프롬프트가 결정론 스크립트 `install.py` 를 호출하게 만든다 (네스팅 문제도 같이 해결).
- 레포 3층 구조: **개발 레포(개인)** → **배포 레포(팀/org, 최소본)** → **사용자 에이전트 레포들(org)**.
- 동료 클론 시 **인증 프롬프트로 멈출 위험**이 유일한 미검증 리스크 → 가시성을
  **Internal** 로 두고 사내에서 1회 실측 필요.

## 1. GitHub 기능 — 우리한테 필요한 만큼만

| 기능 | 한 줄 정의 | 우리 용도 |
|---|---|---|
| **Organization(조직)** | 레포·사람·팀을 담는 최상위 계정(개인 계정과 별개) | `agentis` 조직을 만들어 배포 레포 + 사용자 에이전트 레포들을 모음 |
| **Team(팀)** | 조직 *안의* 사람 묶음. 권한(읽기/쓰기) 단위 | `maintainers`(대표님, 쓰기) / 나머지는 팀 없이도 Internal이면 읽기 가능 |
| **Repository visibility** | Private(초대제) / **Internal**(전사 GHE 계정 누구나 읽기) / Public | **Internal 강력 권장** — 동료를 일일이 초대 안 해도 클론됨 |
| **Issues** | 레포별 이슈 트래커 + 템플릿 + 라벨 | 피드백·버그·"사내환경 호환성 보고"·"내 에이전트 등록 요청" 창구 |
| **Actions** | 레포 이벤트에 도는 CI 자동화(보통 self-hosted 러너) | 씨드 정적검증 15/15 자동 / 릴리스 zip 자동 빌드 / (v2) 에이전트 인덱싱 |
| **Releases** | 태그에 zip 등 산출물 첨부 | zip 폴백 배포 경로(클론 안 되는 환경용) |

> **핵심 개념 정리**: "팀"은 **조직 없이 단독으로 못 만든다.** 대표님이 GHE에서 본 "팀"은
> 십중팔구 *이미 있는 어떤 조직 안의 팀* 이거나, *조직 생성* 화면입니다. 우리가 원하는 건
> **조직(Organization)** 입니다. 조직을 만들고 → 그 안에 배포 레포 → 필요하면 팀으로 권한 정리.

## 2. 레포 3층 구조 (권장 설계)

```
[외부] github.com/imejaim/agentis            ← 원개발 (참고용, 사내에서 접근X 가정)
   │  (대표님이 손으로 내려받아 사내로 가져옴 — 현재 방식 유지)
   ▼
[사내·개인] github.sec.samsung.net/dongho-yoon/agentis      ← ① 개발 레포 (전체: PLAN, docs, examples, kit, seed)
   │  (배포 추출 스크립트 / Action 으로 "필요한 것만" 뽑음)
   ▼
[사내·조직] github.sec.samsung.net/<org>/agentis-seed       ← ② 배포 레포 (최소본만)
   │
   ▼
[사내·조직] github.sec.samsung.net/<org>/<사용자>-<에이전트>  ← ③ 사용자들이 자기 에이전트를 올리는 곳
```

- **① 개발 레포 = 개인 하위 그대로** (`dongho-yoon/agentis`). 지저분한 것(reference/,
  PLAN, 예제) 다 여기. 작업은 계속 여기서.
- **② 배포 레포 = 조직 하위, 딱 필요한 것만**:
  ```
  agentis-seed/
    README.md                  ← 복붙용 Cline 설치 프롬프트
    install.py                 ← 결정론 설치 스크립트 (네스팅·부트스트랩 해결)
    install.sh / install.bat   ← OS별 실행 보조
    .clinerules/agentis.md     ← 씨드 (개발 레포 seed/agentis.md 미러)
    .clinerules/10-agent-routing.md
    seed/10-agent-routing.md   ← install.py 소스 호환용
    kit/agentis-template/      ← 키트 전체 (graph/workflows/memory/skills 템플릿 포함)
    DIST-MANIFEST.json         ← 파일 목록/sha256
  ```
- **③ 사용자 에이전트 레포** = 동료가 자기 `agentis/` 를 브랜치 내보내기 → 조직에 레포로
  push. 토픽 `agentis-agent` 달기. → 모이면 "에이전티스 세상"(자동 인덱싱은 v2).

### 개발 → 배포 추출
개발 레포에 `tools/build-dist.py`(stdlib) 하나: `seed/agentis.md` 복사하면서 URL을
사내 배포 레포 주소로 치환 + `kit/agentis-template/` 복사 + `install.py`·README 생성
→ `_dist/agentis-seed/` 산출 → 그 폴더를 배포 레포로 push. (수동 1커맨드, 또는 Action.)

## 3. 부트스트랩 역설 + 네스팅 문제 → `install.py` 로 동시 해결

**문제 A (부트스트랩)**: 맨몸 Cline은 Agentis 규약을 모름 → "URL만" 으론 못 셋업.
**문제 B (네스팅)**: `git clone URL` 하면 `URL`이름 폴더가 생겨서 `.clinerules` 가
프로젝트 루트가 아니라 그 하위에 박힘. zip 풀 때도 같은 문제.

**해법**: 배포 레포 루트에 **`install.py`** (stdlib only — 결정론 우선 원칙과 동일 결).
역할: 자기 위치에서 `.clinerules/agentis.md` 를 **타깃(기본=현재 작업폴더) 루트**로,
`kit/agentis-template/` 를 타깃 루트에 `agentis/` 로 복사. 멱등(idempotent). 끝나면
다음 한마디(`안녕`) 안내 출력.

**우리가 배포하는 "제품" = URL + 이 복붙 블록** (README 최상단 + 사내 안내문):

```
이 사내 GitHub 레포를 지금 이 작업 폴더에 셋업해줘:
https://github.sec.samsung.net/<org>/agentis-seed

순서:
1) 작업 폴더 안 임시 폴더에 git clone (clone 자격증명 물으면 사내 GHE 계정으로).
2) 클론 폴더에서  python install.py  를 이 작업 폴더(프로젝트 루트) 대상으로 실행.
3) 임시 클론 폴더 삭제.
4) 다 되면 나에게 "안녕" 이라고 말 걸어줘 — 거기서부터 인터뷰 시작.
```

- 이러면 Cline이 한 번에: 클론 → `install.py` → `.clinerules/agentis.md`+`agentis/`
  루트 배치 → 정리 → 워크스페이스 룰 자동 인식 → "안녕"으로 진입. **A·B 동시 해결.**
- **zip 폴백도 통일**: zip 안에도 `install.py` 동봉 → "압축 풀고 install.py 실행해줘"
  로 끝. 폴더명 네스팅돼도 install.py가 루트로 올려줌.

## 4. Issues / Actions 활용안

### 4-1. Issues (배포 레포에 켜기)
이슈 템플릿 3종 + 라벨:
- **버그/오작동** (`bug`)
- **사내환경 호환성 보고** (`compat`) — cline SR이 룰/워크플로우 중 뭘 못 먹는지.
  씨드 개선의 1차 입력. (Phase 0 미검증 항목 회수 창구.)
- **내 에이전트 등록 요청** (`agent-register`) — 동료가 자기 에이전트를 조직에 올리고
  싶을 때. 대표님이 보고 조직 레포 생성/권한 부여.

> 동료 온보딩: 동료들은 GHE 계정이 다 있으니 **배포 레포만 Internal이면 클론에 초대
> 불필요.** 쓰기(자기 에이전트 push)가 필요할 때만 이슈 → 조직 멤버 추가 or 레포 생성.

### 4-2. Actions (있으면 좋은 것, 우선순위 순)
1. **seed-validate** — 배포/개발 레포 push 시 정적검증 15/15 + 스크립트 스모크 →
   배포본이 항상 건강함 보장. (러너만 있으면 바로 가치.)
2. **release-zip** — 태그 push 시 starter zip 빌드 → GHE Release 첨부 (zip 폴백 자동화).
3. **dist-sync** — 개발 레포 변경 → 배포 레포로 추출본 자동 push (`build-dist.py` 실행).
4. **agent-index (v2)** — 조직에서 토픽 `agentis-agent` 달린 레포 스캔 → 레지스트리/
   목록 페이지 갱신. "에이전트가 모이는 곳"의 자동화 1단계.

> ⚠️ **하면 안 되는 것**: 사내 Actions 러너가 *외부* github.com(`imejaim/agentis`)로
> 나가서 자동 미러링 — 사내망 아웃바운드 차단으로 거의 불가. **외부→사내 미러는
> 계속 대표님 수동**(현 방식)이 현실적. 사내 안에서의 자동화만 Action으로.

## 5. 검증 안 된 것 / 대표님이 GHE에서 확인할 것

1. **조직(Organization) 생성 권한** — GHE 우상단 `+` → "New organization" 이 보이나?
   안 보이면 사내 IT 승인/요청 필요(엔터프라이즈는 보통 관리자 통제). → 안 되면
   대안: 이미 속한 팀의 기존 조직 빌려 쓰기, 또는 당분간 개인 레포 1개로 배포만.
2. **레포 가시성에 Internal 옵션이 있나** — 레포 생성 시 Private/Internal/Public 중
   Internal 선택 가능? (이게 있어야 무초대 배포가 됨. 없으면 동료를 멤버로 추가해야 함.)
3. **Actions 러너 존재** — 레포 Settings→Actions, self-hosted 러너 사용 가능?
   없으면 검증/릴리스 자동화는 보류(수동으로 대체 가능, 치명적 아님).
4. **동료 깨끗한 PC에서 첫 clone 인증** — git 설치는 확인됨(✓). 미검증은
   "동료 계정으로 `git clone https://github.sec.samsung.net/...` 시 비대화로 통과되나".
   멈추면 → 사내 안내문에 "최초 1회 자격증명 입력" 또는 PAT 발급 절차 1줄 추가.
