## InfraNodus 사내(cline SR) 적용 가능성

- **InfraNodus 직접 사용 = 사내 부적합** (현재 판단):
  - 유료 SaaS — 그래프 분석을 InfraNodus 서버로 전송 → **사내 자료의 외부 유출** = 보안 정책 위배 가능성 ↑
  - IDE 확장팩·Obsidian 플러그인·MCP 서버 셋 다 결국 InfraNodus 백엔드 호출 → 사내 프록시·인증서 친화적이지 않음
  - 사내 가입·결제 절차 자체가 장벽
- **하지만 영상의 본질은 도구가 아니라 방법론**. 우리는 그 방법론을 자체완결로 흡수한다 → 이 문서의 "4대 방법론" 절이 정확히 그 자리.
- **Agentis 의 자체완결 대응** (v1.4 부터):
  | InfraNodus 기능 | Agentis 대응 |
  |---|---|
  | 3D 그래프 시각화 | `build_graph.py` 가 Three.js + 3d-force-graph **인라인** 으로 자체완결 graph.html 생성 (외부 의존 0) |
  | 군집(clusters) 색 | `[[..]]` 링크 그래프에 커뮤니티 검출(Louvain-lite 또는 폴더 기반 클러스터) → 색 분리 |
  | 공백(content gaps) | 클러스터 간 약한 연결 영역을 자동 식별 → `agentis/memory/gaps.md` 리포트 (선택: 시각화에 빈 영역 강조) |
  | MCP 서버 | v2+ 후보. 사내 cline SR 이 MCP 지원하므로 길은 열려 있음. 외부 InfraNodus 가 아니라 **로컬 MCP** (SQLite/JSON 그래프 쿼리) |
  | Obsidian 플러그인 | 우리 메모리뱅크 자체가 Obsidian 호환 마크다운 + `[[..]]` 링크 → 사용자가 원하면 그냥 Obsidian 으로 열면 됨 (선택 사항, 추가 설치 0) |

기존 LLM Wiki = **"책들이 꽂혀 있는 도서관"** — 문서는 늘어나지만 LLM은 각 문서를 개별로만 본다.
보완된 방법론 = **"책들 간 연결을 알고, 비어 있는 칸(지식의 공백)을 스스로 인지하는 사서"** = 지식 그래프를 사서로 탑재.

## 4대 방법론

### ① 온톨로지 기반의 '살아있는 기억'
- 문제: 문서가 늘어나도 LLM은 전체 시스템의 '상태'·'성장 방향'을 모름.
- 해결: 모든 지식을 **개념(Node) + 관계(Edge)** 로 정의한 온톨로지 그래프를 위키 안에 저장. 대화 시작 시 LLM이 "내가 지금 어떤 지식들을 갖고 있는지"를 구조로 먼저 읽음.
- **Agentis 정렬도**: ⭐⭐⭐ 이미 v1.0~v1.3에서 `agentis/memory/` + `[[..]]` 링크 + `_index.md` + `build_graph.py` 형태로 출발선에 있음. 다음 단계로 "**`agent.md` 머리에 그래프 요약을 자동 인라인**" (예: 상위 5 허브 노드, 클러스터 수)을 박으면 1번이 더 강해진다.

### ② '구조적 공백(Content Gaps)' 시각화 및 탐지
- 방법: InfraNodus 같은 그래프 도구로 군집(clusters)과 그 사이의 빈 공간을 본다.
- 활용: LLM에게 "연결되지 않은 두 군집을 잇는 아이디어 제안해줘" → 시스템이 자기 결핍을 인지하고 스스로 메움.
- **Agentis 정렬도**: ⭐⭐⭐ **v1.4 3D 그래프에 정확히 반영 가능.** 클러스터 색 분리 + 클러스터 간 빈 공간 강조 + "공백 후보" 리포트(`agentis/memory/gaps.md`)를 build_graph.py 가 자동 생성하게 만들면 InfraNodus 의 핵심 효용을 사내 자체완결로 가져옴.

### ③ MCP를 통한 추론 엔진 고도화
- 방법: 텍스트 검색(RAG) 수준을 넘어, 그래프 DB 에 직접 쿼리하는 MCP 서버 활용.
- 효과: LLM이 *"A와 B 사이에 C 라는 연결 고리가 있는데, D 라는 관점은 아직 데이터가 부족합니다"* 같은 자기성찰적 답변.
- **Agentis 정렬도**: ⭐⭐ 사내 cline SR 가 MCP 지원하므로 길은 열려 있다. v2+ 영역. 후보 구성: SQLite(대화 로그) + 그래프 JSON(개념 관계) + 얇은 MCP 서버 한 개. 사내 보안 영향 작음(로컬).

### ④ 자기 참조적(Self-Referential) 문서화 루틴
- 방법: 작업 후 LLM이 "이 지식이 기존 그래프의 어디에 연결되는지" 스스로 판단해 그래프 업데이트.
- 효과: 지식이 쌓이는 게 아니라 **유기적으로 결합**, 시스템이 "스스로 진화하는 지능"이 됨.
- **Agentis 정렬도**: ⭐⭐⭐ 씨드 §3-4 작업 루프(기억 갱신 + 새 개념/엔티티 페이지 + [[..]] 링크 + log) 가 이미 이 절차. **추가로 박을 것**: "기억 갱신 시 build_graph.py 가 새 노드의 *연결 추천*(기존 페이지 중 유사도 높은 5개) 을 출력 → 사용자가 [[..]] 링크 추가 결정." 결정론 + LLM 의미판단 분담의 좋은 자리.

## 기술 스택 메모 (대표님 언급)

- **대화 로그 → SQLite** : 추적·검색 쉽고 로컬 자체완결, 스키마로 정합성.
- **지식 → RAG / GraphRAG** : 의미 검색 + 그래프 경로 추론.
- **Agentis 적용 시 우선순위**:
  1. **GraphRAG-lite** : 우리는 이미 `[[..]]` 링크 그래프가 있음 → 검색 시 키워드 매칭 + 1-hop 이웃 확장 정도면 결정론적으로 가능 (stdlib).
  2. **SQLite 대화 로그** : `agentis/.history/sessions.db` 같은 위치. v2 후보. cline SR 대화 export 가 가능한지 확인 필요.
  3. **임베딩 기반 RAG** : 사내 모델 임베딩 가용성에 의존. v3 영역.
