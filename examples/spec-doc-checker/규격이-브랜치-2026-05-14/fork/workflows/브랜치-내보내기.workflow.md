# 브랜치 내보내기

이 에이전트의 진화된 결과를 다른 사용자(동료)에게 넘길 수 있는 폴더로 묶는다. **씨드 → 브랜치 → 메인** 세 단계 중 "브랜치 잘라서 송신" 단계.

> 용어 안내: 사용자가 "내보내기 / 분신 / 사본 / 복사본 만들어줘" 라고 하면 **"브랜치 만들기"** 로 안내하라. 동료들 사이 용어 통일.

## 절차

1. **인터뷰** (한 번에 한 질문, 보통 1~2회 끝):
   - 자동 제외 정책 설명: 사용자 본인 식별 정보(`agent.md` 안), 본인 엔티티 페이지, `share: private` 태그 페이지.
   - 추가 제외 의사 확인: "더 빼고 싶은 게 있을까요? 없으면 '없음' 이라고 답해주세요."

2. **실행** (결정론):
   ```
   python agentis/workflows/브랜치-내보내기.py [--extra-exclude memory/sources/2026-05-08-시험성적서-모델X.md,memory/hot.md]
   ```

3. **검증** (콘솔):
   - 통계: 포함 N파일 / 제외 M파일 (자동 / 사용자 지정)
   - 의심 누출 경고: 사람 이름 / `[REDACTED]` 잔류 / 소스 링크 등이 fork 본문에 남아있는지 보고
   - 출력 폴더 경로 + `BRANCH.md` 보기 안내

4. **사람 게이트**: 사용자에게 **`BRANCH.md` 를 보여주고 검토 요청**. ("의심 누출 경고가 N건 있어요. 한번 봐주세요.") 사내 도구 — 사람 검토가 마지막 안전망.

5. **송신**: 검토 통과하면 폴더 zip / 사내 깃 push / 메일. 받는 쪽 안내문(`BRANCH.md` 첫 절) 같이.

6. **기억 갱신**: `memory/log.md` 에 한 줄: `## [날짜] note | <상대>에게 브랜치 송신 (포함 N / 제외 M)`.

## 주의

- 인터뷰에서 추가 제외 받을 때 명시적으로 묻는다. "별도 제외 없으면 케이스 데이터까지 다 같이 가요" 가 보낸 사람 의도와 맞는지 확인.
- 본문에 사람 이름이 자유 형식으로 박혀있으면 자동 REDACT 가 다 잡지 못한다 → `BRANCH.md` 의 의심 누출 경고를 사람이 한번 훑어야 함.
- 브랜치 폴더는 만든 뒤 작업 폴더 옆에 그대로 둔다 (gitignore 권장 패턴: `*-브랜치-*/`).

## 관련
- 받는 쪽: 브랜치 폴더를 작업 폴더에 두고 "안녕" → 씨드가 자동 감지해서 [리브랜드(§5-2)] 또는 [팩 모드(§5-3)] 로 분기
- 메인: `agent.md` 에 `main_repo:` 가 설정돼 있으면 [메인-동기화](메인-동기화.workflow.md) 가 이 스크립트를 내부에서 호출해서 push-prep 폴더 만든다
