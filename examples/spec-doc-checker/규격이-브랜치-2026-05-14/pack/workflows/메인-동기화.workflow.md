# 메인 동기화

사내 깃에 **메인(main) 에이전트** 레포가 있을 때, 내 에이전트와 동기화한다. (§5-4)

**활성 조건**: `agent.md` 에 `main_repo: <URL>` 가 들어있고 비어있지 않을 때만. 없으면 이 워크플로우는 동작 안 함 — 메인 개념 자체가 비활성.

## 모드

### `--check` — 디프 빠르게 보기
```
python agentis/workflows/메인-동기화.py --check
```
메인 레포를 임시 디렉토리에 클론 → `브랜치-비교.py` 로 디프 요약. "메인에 무엇이 추가됐는지 / 내가 무엇을 갖고 있는지" 한눈에.

### `--pull` — 메인의 변경을 내 에이전트에 가져오기
```
python agentis/workflows/메인-동기화.py --pull
```
메인 레포를 임시로 클론 → 그 pack/ 처럼 취급 → `팩-병합.py` 흐름. 처음엔 `--strategy plan-only` 로 충돌 미리보고, 사용자가 결정 후 실제 머지.

### `--push-prep` — 내 변경을 메인에 올릴 준비
```
python agentis/workflows/메인-동기화.py --push-prep
```
`브랜치-내보내기.py` 를 내부적으로 호출해 `<에이전트이름>-브랜치-YYYY-MM-DD/` 를 만든다. 그리고 사용자에게 **수동 git 명령**을 안내:
```
cd <메인 레포 클론 폴더>
# 채택할 변경만 골라 복사 (관리자가 함)
# git add . ; git commit -m "<설명>" ; git push
```
> 실제 `git push` 는 사용자(또는 관리자)가 자기 권한으로 수행. 스크립트가 자동 푸시하지 않는다 (보안 경계).

## 주의 / 안전

- 메인 레포의 구조는 **루트에 `agent.md` + `memory/` + `skills/` + `workflows/`** 가 있는 형태를 가정한다. 다르면 `--repo-subpath <경로>` 로 안의 위치 지정.
- `git` 이 설치돼 있어야 함. 없으면 에러로 종료.
- 사내망 인증서 문제로 클론 실패 시 가이드 메시지 출력. 사내 깃 사용자명/토큰은 사용자 환경 (`git config --global` 또는 `~/.git-credentials`) 그대로 사용 — 스크립트가 직접 다루지 않음.

## 관련
- 메인 큐레이션(여러 사람 브랜치 → 메인 갱신)은 관리자가 [브랜치-비교](브랜치-비교.workflow.md) 보고 결정해서 메인 레포에 직접 커밋.
