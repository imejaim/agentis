# 팩 병합 (다른 에이전트의 역량만 가져오기)

이미 자기 에이전트가 있는 상태에서 다른 사람의 브랜치에서 **역량(skills + workflows + 도메인 개념)만** 가져와 합친다. (§5-3 팩 모드)

**절대 안 건드리는 것**: `agent.md`, `memory/sources`, `memory/entities`, `memory/log.md`, `memory/hot.md`, `memory/overview.md`, `memory/_index.md`. (이 안전 보장이 팩 모드의 핵심)

## 절차

1. **충돌 미리보기** (먼저 항상 이거):
   ```
   python agentis/workflows/팩-병합.py --pack <브랜치폴더>/pack --strategy plan-only
   ```
   같은 이름의 스킬/워크플로우/개념 페이지가 있는지 보고서로 받음. 새것/충돌/추가 가능 항목 통계.

2. **충돌이 있으면** 한 건씩 사용자에게 물어본다:
   - 덮어쓰기 (overwrite): 팩의 새 버전으로 교체
   - 내 것 유지 (keep-mine): 내 기존 것을 그대로
   - 둘 다 (rename-incoming): 팩의 것을 `<원이름>-import` 로 이름 바꿔서 같이 두기

3. **결정 반영해 실제 머지**:
   ```
   python agentis/workflows/팩-병합.py --pack <브랜치폴더>/pack --strategy <overwrite|keep-mine|rename-incoming>
   ```
   (모든 충돌에 동일 정책 적용. 건별로 다르게 하고 싶으면 여러 번 실행하며 `--only` 로 좁히기.)

4. **검증**:
   - 콘솔: 추가 / 덮어쓰기 / 스킵 통계 + 안전 보장(agent.md 등 안 건드림) 확인 메시지
   - 머지 후 `python agentis/graph/build_graph.py` 한 번 돌려 그래프 갱신

5. **기억 갱신**: `memory/log.md` 에 `## [날짜] ingest | <팩 출처>의 pack 병합 (skills +N / workflows +M / concepts +K)`. `hot.md` 에 "새 스킬 X 검토" 메모 한 줄.

## 주의

- 팩의 `pack.meta.md` 를 먼저 읽어 출처·범위를 확인하고 사용자에게 알린다.
- 충돌 시 사용자에게 무엇이 달라지는지(파일 크기 변화·H1 비교) 짧게 보여주면 결정이 쉬워진다.
- 같은 사람이 같은 팩을 두 번 머지하지 않도록 `log.md` 의 ingest 기록을 먼저 확인한다.

## 관련
- 받는 쪽 분기: 작업 폴더에 `agentis/` 가 **없으면** [리브랜드 모드(§5-2)]로 자동 분기됨 (이 워크플로우 호출 안 됨)
- 메인: `메인-동기화.py --pull` 이 내부적으로 이 워크플로우를 호출
